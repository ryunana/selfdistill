# PR #5 真实数据修复设计

**状态：** 已由用户逐部分确认
**范围：** ChatGPT、Gemini、DeepSeek、本地 Codex、本地 Claude Code 导入
**原则：** 保留真实对话，不混入系统内容，不静默丢失，不伪造会话结构

## 1. 为什么要修

PR #5 已经能生成 Markdown，基础权限和重复导入也能正常工作。但是，用真实导出数据复测后发现，“成功生成文件”不等于“正确还原会话”：

- DeepSeek 的互斥分支会被拼成一条假对话。
- Gemini 的多次独立活动会被拼成一个超长会话。
- ChatGPT 的图片内部信息会进入蒸馏正文。
- Codex 的清洗规则可能把用户自己写的 XML 或代码删除。
- Claude Code 的内部命令和元数据会被当成用户对话。
- 切换对话分支后，文件内容与去重记录可能不一致。

这些问题会直接污染后续个人档案，因此必须在合并 PR 前修复。

## 2. 本次目标

1. 五类来源都能输出真实、可理解的对话结构。
2. 系统注入、内部命令、模型思考和工具过程不进入蒸馏正文。
3. 用户自己写的文字、XML、代码和提示词不被误删。
4. Markdown 文件与 `.imported.json` 永远表示同一份已导入结果。
5. 报告如实区分成功、更新、跳过、部分成功和失败。

## 3. 非目标

- 不加入云端模型或第三方依赖。
- 不改造后续蒸馏、审批或 canonical 写回流程。
- 不保留或解析模型隐藏推理。
- 不为所有未来导出格式建设通用插件平台。
- 不在修复完成后自动合并 PR。

## 4. 总体方案

保留当前“纯 Python 标准库，一个入口命令”的使用方式，但将内部职责分清：

1. **来源识别：** 确定文件来自哪个平台。
2. **来源解析：** 将原始数据还原为会话、分支和消息。
3. **安全清洗：** 只删除能够明确判定为内部内容的部分。
4. **统一输出：** 将各来源结果写成现有 Markdown 格式。
5. **状态对账：** 写入完成后，用实际文件中的消息生成去重记录。
6. **诚实报告：** 告诉用户发现了什么、写入了什么、没写入什么以及原因。

这是“适度整理后修复”，不做全面重写。

## 5. 各来源的处理规则

### 5.1 ChatGPT

- 继续沿 `current_node` 保留当前活动分支。
- 用户文字原样保留。
- 图片结构转成 `[图片]`，不输出内部地址、资产指针或元数据字典。
- `thoughts`、`reasoning_recap` 等内部内容保持排除。
- 导出中缺少有效 `current_node` 时，不再按时间压平：只有一个有效叶子时保留该完整路径，存在多个叶子时按完整路径拆成独立分支会话。

### 5.2 Gemini

- 一次 `Prompted` 活动对应一份独立会话。
- 将该次用户问题、附件和对应回答绑定在一起。
- 使用该次活动的时间，不再让大量用户消息显示“未知”。
- 按时间从旧到新输出。
- 会话 ID 由活动时间和该次活动的内容指纹稳定生成，不使用会随新导出漂移的全局序号。
- 消息 ID 结合会话 ID、角色和会话内顺序；即使用户在不同时间重复问同一句话，也不会被误当成重复数据。
- 如果无法可靠确定活动边界，停止写入并提示使用手工整理备选方案。

### 5.3 DeepSeek

- 普通无分支会话保持一份输出。
- 出现分支时，从根节点到每个有效叶子节点分别生成完整路径。
- 每条路径输出为独立会话，显示稳定的“分支 1 / 分支 2”标识。
- 分支会话 ID 根据节点路径指纹稳定生成，同一导出重复导入时文件名不漂移；“分支 1 / 分支 2”只是展示名称。
- THINK 和工具过程默认排除；附件保留为可读占位。

### 5.4 Codex

- 仅删除已知且具有完整边界的 Codex 系统包装块。
- 不再将 `<name>`、`<path>`、`<string>`、`<prompt>` 等通用标签单独视为系统内容。
- 图片标记转成 `[图片]`。
- 中断说明、AGENTS 指令和 Automation 注入必须以整块规则排除，不留下尾部说明。
- 无法确定是系统内容还是用户正文时，默认保留用户正文，并在审计统计中标记。

### 5.5 Claude Code

- `isMeta=true` 的记录不进入对话。
- 命令名、命令消息、本地命令说明和后台任务通知不进入对话。
- 只保留真实用户输入和用户可见的助手回答。
- 对未来未识别的内部记录进行计数和告警，不静默混入。

## 6. 增量导入与文件安全

- 每次导入都将“本次解析出的有效完整会话”与现有文件对账。
- 只有纯粹新增消息时才追加。
- 会话分支、顺序或已有消息发生变化时，重建导入器管理的消息区块。
- 重建后，`.imported.json` 从最终实际写入的消息 ID 重新生成。
- 保留标记区块之外的用户手工内容。
- 如果标记缺失、重复或结构损坏，停止覆盖并报错。
- 写入继续使用原子替换，目录保持 `0700`，文件和状态保持 `0600`。

## 7. 状态损坏与错误处理

- `.imported.json` 无法解析时立即停止，不将其当成空状态。
- 损坏状态文件保持原样，报错信息给出实际路径和恢复方向。
- 全部来源都损坏或无法识别时，命令返回失败。
- 一部分来源成功、一部分失败时，已成功的可保留，报告明确显示“部分成功”。
- 任何被跳过的会话都必须有可理解的原因。

## 8. 本地发现与 dry-run

- 默认自动发现仍扫描 Codex 和 Claude Code 各自的标准目录。
- 使用 `local --path` 时，通过文件结构判断来源，不将同一文件同时当成两种来源。
- 无法稳定判断时，命令停止并提示使用 `--local-format codex` 或 `--local-format claude`，不猜测。
- dry-run 报告分别显示：发现、预计新导入、预计更新、预计重复跳过、解析失败。
- dry-run 不创建目录、Markdown 或状态文件。

## 9. 兼容性

- 用户入口仍为 `python3 import_chats.py`。
- 现有 `--source chatgpt|gemini|deepseek|local`、`--path`、`--since`、`--exclude`、`--dry-run`、`--yes` 继续可用。
- 新增可选的 `--local-format auto|codex|claude`，默认为 `auto`，只在 `local --path` 无法自动判断时需要用户指定。
- 现有 Markdown 头部、`conversation_id`、`message_id`、`exported_at` 和消息区块标记保持兼容。
- DeepSeek 分支会话和 Gemini 活动会产生新的稳定会话 ID，这是修正错误结构所必需的有意变化。

## 10. 测试与验收

### 10.1 自动回归测试

至少覆盖：

- ChatGPT 当前分支、图片占位和内部推理排除。
- Gemini 多活动拆分、时间顺序、附件、重复问题不重复 ID。
- DeepSeek 无分支和多分支路径。
- Codex 系统注入清理以及普通 XML/代码保留。
- Claude `isMeta` 和内部命令排除。
- 新消息追加、分支切换、状态对账、标记损坏停止。
- 损坏 `.imported.json`、全部损坏来源、部分成功。
- `local --path` 来源判断和 dry-run 真实预计数。
- `0700/0600` 权限与原子写入。

### 10.2 真实数据聚合验收

重新运行用户提供的 ChatGPT、Gemini、DeepSeek 导出，以及本地 Codex、Claude Code 会话。验收输出只包含数量和异常统计，不展示标题或对话正文。

必须同时满足：

- DeepSeek 不存在分支混写。
- Gemini 每次活动独立对应，不再生成一个超长会话。
- ChatGPT 输出不含图片内部元数据。
- Codex 普通 XML 正文保留，已知系统注入无残留。
- Claude 输出不含元数据和内部命令。
- 分支切换后 Markdown 与 `.imported.json` 完全一致。
- 重复导入不产生重复消息。

### 10.3 合并前门槛

- 全部自动测试通过。
- Python 语法检查通过。
- 发布隐私扫描通过。
- `git diff --check` 通过。
- 工作区和远端 PR 提交状态核对清楚。
- 新的只读 Sol 终审给出 `ship`。
- 展示完整验收结果后，由用户决定是否合并。

## 11. 交付结果

修复完成时，用户应得到：

1. 已修复的 PR 分支。
2. 新增的脱敏回归测试。
3. 五类真实数据的聚合验收结果。
4. 独立 Sol 终审结论。
5. 明确的“可合并”或“仍需修复”结论，不以“文件已生成”代替内容正确性。
