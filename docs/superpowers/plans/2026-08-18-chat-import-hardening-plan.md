# PR #5 导入器修复实施计划

**依据：** `docs/superpowers/specs/2026-08-18-chat-import-hardening-design.md`
**实施范围：** `import_chats.py`、`tests/test_chat_import.py`、必要的脱敏 fixture、README 与 intake 说明
**不在范围：** 蒸馏 prompt、canonical 写回、云端模型、第三方依赖、通用插件框架

## 总体验收标准

完成必须同时满足：

1. 五类来源的脱敏自动回归测试通过。
2. 用户的五类真实数据通过聚合验收，不展示对话正文。
3. 分支、消息顺序、附件占位、系统内容过滤和增量状态符合已批准设计。
4. 损坏状态和无法识别的输入明确失败，不静默重置或报告成功。
5. 目录仍为 `0700`，Markdown 和状态文件仍为 `0600`，写入仍为原子替换。
6. 整库测试、语法检查、隐私扫描和 `git diff --check` 通过。
7. 新的只读 Sol 终审给出 `ship`。

## 任务 1：先建立统一的结构与测试护栏

**目标：** 不改变用户命令入口，先把会话路径、稳定 ID、附件占位和报告计数的共用规则收口。

### 实施

- 在 `import_chats.py` 中增加小型内部辅助函数，不引入外部框架：
  - 根据 parent/children 关系找出完整根到叶路径。
  - 检测循环、断链、重复节点和空路径。
  - 根据来源 ID 或路径指纹生成稳定会话 ID。
  - 对无原生 ID 的消息生成会话内唯一 ID。
  - 将图片和附件结构转换为统一可读占位。
- 保留现有 parser 对外返回格式，避免无关重写。
- 将“输入会话数”、“输出会话数”、“被安全排除的内部片段数”、“解析失败数”分开计数，不再混用“跳过 N 条”。

### 先写的测试

- 单路径、一次分叉、多层分叉和循环损坏。
- 同一路径重复解析产生相同 ID。
- 不同分支产生不同 ID。
- 同一会话中的消息 ID 不重复。
- 图片元数据不出现在输出文本中。

### 任务验收

```bash
python3 -m unittest tests.test_chat_import -v
```

新增共用规则测试先失败，实现后通过；原有用例不回归。

## 任务 2：修正 ChatGPT 和 Gemini

### 2.1 ChatGPT

**实施：**

- `current_node` 有效时，只保留根到当前节点的路径。
- `current_node` 缺失但只有一个叶子时，保留该路径。
- `current_node` 缺失且有多个叶子时，每条完整路径生成稳定分支会话。
- 文字 part 原样保留；已知图片 part 转为 `[图片]`。
- 未识别的结构化 part 转为 `[未识别附件]` 并在报告中计数，不直接字符串化内部字典。
- 继续排除空的 `thoughts` 和 `reasoning_recap` 记录。

**回归测试：**

- 活动分支保留、备选分支排除。
- 无 `current_node` 的单路径与多路径。
- 文字+图片的多模态用户消息。
- 输出不包含 `asset_pointer`、图片尺寸或 Python 字典字符串。

### 2.2 Gemini

**实施：**

- 利用 Takeout 活动容器边界拆分条目，不再对整份 HTML 做一条全局消息流。
- 每个活动块中，绑定 Prompted 用户内容、附件、该块的活动时间和可见回答。
- 一个活动块生成一个会话；没有回答的活动仍保留用户消息。
- 会话按活动时间从旧到新返回。
- 会话 ID 使用“活动时间+活动内容指纹”；消息 ID 使用“会话 ID+角色+会话内顺序”。
- 活动边界无法稳定识别时报错，不生成伪会话。

**回归测试：**

- 两次独立活动生成两份会话。
- 时间从旧到新，用户和助手使用同一活动时间。
- 不同时间重复同一问题仍有不同会话 ID 和消息 ID。
- 新的 Takeout 在头部增加活动时，旧活动 ID 不改变。
- 附件和无回答活动正确保留。

### 任务验收

```bash
python3 -m unittest tests.test_chat_import.ParserTests -v
```

## 任务 3：修正 DeepSeek 分支

**实施：**

- 根据 mapping 的 parent 关系生成根到叶子路径。
- 工具专用节点参与路径连接，但不输出到正文。
- 每条路径只输出该路径上的 REQUEST、RESPONSE 和可读附件。
- 无分支时保持原会话 ID。
- 有分支时使用 `原会话ID--branch-路径指纹` 作为稳定 ID，标题显示“分支 N”。
- 循环、断链或无有效消息路径进入错误报告，不压平兜底。
- THINK 继续默认排除；工具片段改为独立的“内部片段排除数”，不冒充被跳过会话数。

**回归测试：**

- REQUEST 之后多个 RESPONSE 分支。
- RESPONSE 之后多个 REQUEST 分支。
- 多层分支和公共前缀。
- 各分支互不包含对方的互斥节点。
- 重复导入时分支 ID 和文件名稳定。
- 工具片段、THINK 和附件的统计口径正确。

## 任务 4：收紧 Codex 和 Claude Code 过滤

### 4.1 Codex

**实施：**

- 用“可确认的外层包装”替代“通用标签黑名单”。
- 仅在已知系统外层内清理 `name/path/string/prompt/skill` 等内层标签；用户正文中的同名标签原样保留。

- `<turn_aborted>` 中断通知以完整记录排除，不留下说明尾巴。

- 用户正文中的 `<name>`、`<path>`、`<string>`、`<prompt>` 全部保留。
- 同一记录同时包含系统包装和用户正文时，只删包装。

**回归测试：**

## 任务 5：重做增量对账与错误语义

### 5.1 Markdown 是实际真相

- 读取现有 Markdown 时必须正好存在一对消息区块标记。
- 标记之外的标题、说明和用户手工内容保留。
- 本次完整消息序列与现有区块完全相同时，返回重复跳过。
- 本次序列是现有序列的纯追加时，可追加新消息。
- 分支、顺序或已有消息变化时，重建整个消息区块。
- 每次写入后，状态中的 message IDs 由最终区块重建，不与旧状态做无限并集。
- 如果文件写入成功、状态写入前中断，下次运行以 Markdown 实际区块自动重建状态。
- 同一会话出现重复 message ID 时停止写入并报错。

### 5.2 状态和输入错误

- `.imported.json` 损坏时抛出可理解错误，不返回空字典。
- 所有输入都损坏或都无消息时，命令返回 `1`。
- 部分成功、部分解析或写入失败时，保留已成功输出，命令返回 `2`。
- 全部成功或只有已识别的安全排除项时，命令返回 `0`。
- 已知 THINK、工具片段和系统元数据属于信息性统计，不单独导致非零返回码。

### 回归测试

- 新消息追加。
- ChatGPT 分支切换后再切回，文件和状态都能正确恢复。
- 文件中的手工前言和尾注保留。
- 缺失标记、重复标记和重复消息 ID 停止覆盖。
- 文件与状态不同步时能从文件恢复。
- 损坏状态、全失败和部分成功的返回码。

### 任务验收

```bash

```

## 任务 6：修正本地发现、dry-run 和报告

**实施：**

- 默认本地发现继续使用 Codex 和 Claude 各自标准目录。
- `local --path` 只扫描一次 `*.jsonl`，再根据文件顶层结构分类。
- 新增 `--local-format auto|codex|claude`，默认 `auto`；强制类型时只使用对应 parser。
- 自动判断不出来的文件进入失败报告，不重复解析。
- dry-run 完整解析候选会话并与现有文件/状态对账，但不执行写入。
- 报告给出原始会话、输出会话、新导入、更新、重复、解析失败、安全排除片段。

**回归测试：**

- 单一 Codex 目录不再同时识别为 Claude。
- 单一 Claude 目录正确识别。
- 混合目录逐文件正确分类。
- 未知 JSONL 进入失败报告。
- `--local-format` 能覆盖自动判断。
- dry-run 如实报告预计新导入、更新和重复数，且不创建文件。
- 实际跳过原因和内部片段统计不混用。

### 7.3 真实数据验收

- ChatGPT：会话数、消息数、分支数、图片占位数、内部元数据残留数。
- Gemini：活动数、输出会话数、无时间数、重复 ID 数、顺序异常数。
- DeepSeek：原会话数、分支会话数、输出路径数、互斥节点混入数。

- Claude：会话数、用户/助手消息数、meta/sidechain/内部命令残留数。
- 通用：生成文件数、渲染消息数、状态 ID 数、重复导入结果、`0700/0600` 权限。
